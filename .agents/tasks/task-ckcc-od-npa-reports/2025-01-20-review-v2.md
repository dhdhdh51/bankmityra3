# NPA KRM OTS report type, VisitFormData restructure, and HTML report generation (v2)

This change adds the CKCC NPA KRM OTS Scheme as a fourth report type to the field visit app, converts `VisitFormData` from a data class to a regular class to bypass the JVM 255-parameter constructor limit, introduces a full report generation and export pipeline (HTML/PDF via PrintManager, CSV via ExcelExporter), renames "BC Agent" to "BC Supervisor" and "BC code" to "BCBF Code" throughout, and merges the former duplicate print/PDF buttons into a single "Print / Save PDF" action. All five issues from the v1 review have been addressed.

Watch for: the `SupplementaryData` bag passed to ReportGenerator is mostly empty at report-view time, so the generated PDF will have blank fields for branch, district, mobile, aadhaar, outstanding, and overdue (confirmed); NPA OTS validation errors are not wired to inline field highlights or scroll-to-error targeting (confirmed).

**Verdict**: APPROVED

## High-level view

The five v1 issues are resolved: `getSerializableExtra` branches on API level, the dead "View Report" menu in VisitDetailActivity is deleted entirely, the NPA OTS KYC/renewal rows are omitted from the PDF rather than hardcoded to false, the `copy()` method carries a prominent maintenance warning, and the two print buttons are consolidated into one.

`buildSupplementaryData()` in VisitReportActivity only populates four of the nineteen `SupplementaryData` fields (`borrowerName`, `loanAccountNumber`, `bcSupervisorName`, `bcCode`). Branch name, regional office, zone, mobile, aadhaar, outstanding, overdue, and NPA date all render as empty cells in the printed PDF. If the intent is a print-ready document at the doorstep, the Activity needs more data passed through the intent chain.

`showValidationErrors()` has no mappings for `npa_ots_*` error keys, so NPA OTS validation failures produce a toast but no inline error highlight and scroll to the wrong card.

## Sparse SupplementaryData at report-view time

At the point `openReportView()` is called:

```kotlin
private fun buildSupplementaryData(): ReportGenerator.SupplementaryData {
    val customerName = intent.getStringExtra(EXTRA_CUSTOMER_NAME).orEmpty()
    return ReportGenerator.SupplementaryData(
        borrowerName = customerName,
        loanAccountNumber = form.loanAccountId.toString(),
        bcSupervisorName = session.user?.name.orEmpty(),
        bcCode = form.bcbfCode,
    )
}
```

Fields like `branchName`, `branchCode`, `regionalOffice`, `zone`, `cbcName`, `linkedBranch`, `district`, `mobile`, `alternateMobile`, `aadhaarLast4`, `iibfNumber`, `outstandingAmount`, `overdueAmount`, and `npaDate` remain at empty-string defaults. The HTML generator renders these as empty table cells. If the preview is meant only to verify agent-entered sections and the server produces the complete report later, this is acceptable. If it is meant to be printable at the doorstep, the Activity needs the lead's full data passed through the intent chain.

## NPA OTS validation error display gap

`validateCkccNpaOts()` produces errors keyed as `npa_ots_scheme`, `npa_ots_deposit_amount`, `npa_ots_deposit_date`, `npa_ots_deposit_reference`, `npa_ots_validity_to`, and various amount fields. `showValidationErrors()` has no branches for any of these. Compare with OTS errors, where `ots_scheme_other_text` is mapped to `binding.sectionOts.fieldOtsSchemeOther.error`.

The consequence: when an NPA OTS form fails validation, the agent sees a toast but no red highlight on the offending field. The scroll-to-first-error logic falls through to `else -> binding.cardRecommendations` because none of the `when` conditions match NPA OTS keys, scrolling the agent away from the actual problem.

Not tested: the UI wiring in `setUpNpaOts()`, the scroll-to-error behavior for NPA OTS keys, and the `buildSupplementaryData` completeness.
